# 版本迁移指南：旧版 → v1.0

> 本指南帮助将基于旧版架构（3要素方法/4列场景/3层决策树）创建的技能升级到 v1.0 新版架构。

---

## 变更总览

| 维度          | 旧版                     | v1.0 新版                  | 影响范围                     |
| ----------- | ---------------------- | ------------------------ | ------------------------ |
| L2 原子方法格式   | 3 要素（用途 + 伪SQL + 解读规则） | 8 要素结构化格式                | attribution_logic.md §L2 |
| L2 通用方法数量   | MTD-01~07（7个）          | MTD-01~08（8个，新增漏斗转化率）    | attribution_logic.md §L2 |
| L2 业务特有方法编号 | MTD-08+                | MTD-09+（MTD-08 已升为通用方法）  | attribution_logic.md §L2 |
| L3 场景配置列数   | 4 列（ID/名称/触发词/方法链）     | 9 列（+维度/指标/必需输入/固化查询/备注） | attribution_logic.md §L3 |
| L4 决策树结构    | 3 层意图分流（查数/归因/建议）      | 5 步线性路径 + 全局 Checklist   | attribution_logic.md §L4 |
| 查询执行引用      | 硬编码脚本路径                | 技能名引用                    | SKILL.md                 |

---

## 逐步迁移操作

### 第一步：升级 L2 原子方法（工作量：中）

**旧版格式：**

```markdown
### MTD-04 前后对比
**用途**：某事件前后对比指标变化。
**伪 SQL**：...
**解读规则**：变化率 > 10% 视为显著。
```

**新版格式（需补充 5 个要素）：**

```markdown
### MTD-04 前后对比
- **触发：** ← 新增：用户说什么话时触发
- **适用表：** ← 新增：可用在哪些表上
- **参数：** ← 新增：需要传入的变量
- **步骤：** ← 新增：执行的具体步骤
- **伪 SQL：** （保留原有内容）
- **输出：** ← 新增：产出什么
- **陷阱：** ← 新增/替换原"解读规则"：容易出错的地方
- **特别提示：** ← 新增：业务特有注意事项
```

**操作清单：**

- [ ] 为每个现有方法补充「触发」要素（参考 example-snippet.md）
- [ ] 为每个现有方法补充「适用表」要素
- [ ] 为每个现有方法补充「参数」要素（列出所有 ${} 占位符的含义）
- [ ] 为每个现有方法补充「步骤」要素（拆解为有序步骤）
- [ ] 将原「解读规则」拆分到「陷阱」和「特别提示」中
- [ ] 为每个现有方法补充「输出」要素
- [ ] 如果业务域有漏斗分析场景，添加 MTD-08 漏斗转化率（从模板复制）
- [ ] 将业务特有方法的编号从 MTD-08+ 调整为 MTD-09+

### 第二步：扩展 L3 场景配置表（工作量：小）

**旧版 4 列表头：**

```markdown
| 场景 ID | 场景名称 | 触发词 | 方法链 |
```

**新版 9 列表头：**

```markdown
| 场景 ID | 场景名称 | 触发词 | 方法链 | 维度 | 指标 | 必需输入 | 固化查询 | 备注 |
```

**操作清单：**

- [ ] 在现有表格右侧追加 5 列：维度、指标、必需输入、固化查询、备注
- [ ] 为每个场景填写 GROUP BY 字段（维度列）
- [ ] 为每个场景填写引用的 L1 指标 ID（指标列）
- [ ] 为需要用户提供数据的场景填写"必需输入"（含格式要求），无需额外输入填 "—"
- [ ] 为每个场景填写固化查询编号（FQ-XX），未固化填 "—"
- [ ] 为每个场景填写备注（如数据上线日期、已知限制等），无则填 "—"
- [ ] 检查触发词是否包含口语化表达，不足则补充

> **注意**：新版不再包含"关键参数"列。参数（时间窗口、过滤条件、阈值等）由 L2 方法的"参数"要素定义，agent 执行时动态绑定，不在 L3 重复维护。

### 第三步：重构 L4 决策树（工作量：小）

**旧版结构：**

```
用户提问
  ├─ 意图=查数 → ...
  ├─ 意图=归因 → ...
  └─ 意图=要建议 → ...
```

**新版结构：**

```
1. 解析意图
   ├─ 命中 L3 场景？ → 取该场景配置（维度/指标/方法链/固化查询）
   └─ 未命中？ → 用 L2 方法临时编排，并建议沉淀为新场景

2. 前置校验
   ├─ 检查"必需输入"列 → 有未提供的项？向用户索取（目标值/文件等）
   ├─ 涉及枚举/映射未知 → 先跑 MTD-07 探查
   ├─ 时间窗口/切换日未定 → 与用户确认
   ├─ 跨时间点分析？ → 标记需换表
   └─ 查看场景"备注"列 → 注意数据起始日期、覆盖范围等限制

3. 执行路径选择
   ├─ 场景有固化查询（FQ-XX）？
   │   └─ 从 fixed_queries.md 取 SQL → 注入 ${param} → 直接执行 → 跳到第 5 步
   └─ 无固化查询？
       ├─ 选表（L0 选表规则）
       └─ 按方法链顺序执行（L2 步骤 + 伪 SQL）
           └─ 每步校验：窗口等长？体量门槛？度量一致？

4. （可选）固化建议
   └─ 方法链执行完毕、结果经确认正确 → 建议将该 SQL 固化到 fixed_queries.md

5. 输出（按方法"输出"定义）
   └─ 结论区分"统计显著"与"业务显著"，小样本不下强结论
```

**操作清单：**

- [ ] 用新版 5 步结构替换旧版 3 层分流
- [ ] 添加全局 Checklist（5 条校验规则，从模板复制）
- [ ] 保留原有的业务特有路由逻辑，嵌入到第 1 步或第 2 步中

### 第四步：更新 SKILL.md（工作量：极小）

- [ ] 质量校验清单同步到新版（L2 ≥ 8 个、8 要素、L3 9 列、L4 5 步路径）
- [ ] 查询执行章节去除硬编码路径，改为技能名引用
- [ ] 第三步工作流描述同步到新版

### 第五步：运行验证

```bash
bash validate.sh /path/to/your-skill/
```

确保所有检查项通过后再发布。

## 向后兼容性说明

- 旧版技能仍可正常运行，但 agent 可能不会充分利用新架构的优势（如前置校验、体量门槛等）
- 建议在下一次大改时顺带完成迁移
- 迁移过程中保持 metrics_definitions.md 不变（口径唯一权威原则不受版本影响）

## 渐进式引入新功能

旧版技能迁移后，无需一次性填满所有新列。以下两个功能可在日常使用中逐步引入：

### 必需输入（逐步补充）

迁移时所有场景的"必需输入"列可先填 "—"。后续在以下情况发生时再补充：

- **发现 agent 缺少关键输入就直接执行**：如用户问"帮我看看活动商品转化"但没提供商品清单，agent 直接跑了全量数据 → 此时回填 `文件: 活动SKU清单（Excel/CSV，需含商品编码列）`
- **用户主动提到目标值**：如"换货率超过 15% 的要预警" → 回填 `目标值: 换货率阈值（百分比数值）`

每次补充后运行 `bash scripts/validate.sh` 确认格式正确。

### 固化查询（验证后引入）

迁移后所有场景的"固化查询"列先填 "—"。固化查询的引入时机：

1. 某个场景被反复使用（如同一句话问了 3 次以上）
2. 方法链跑出的结果经用户确认正确
3. 用户说"下次直接跑这个就行"

满足以上条件后，按 architecture-guide.md §固化查询 的确认流程操作：征求用户确认 → agent 后台写入 fixed_queries.md → 更新 L3 场景表。

> **原则**：必需输入和固化查询都是"用到时再补"，不需要在迁移时预先填写。
